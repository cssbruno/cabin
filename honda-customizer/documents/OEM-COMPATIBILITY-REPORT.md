# Original Honda compatibility and physical-observation report

`ValidationActivity` performs package preflight for the six native service areas: VehicleInfoManager, UnitInfo, cameras, instrument-panel contents, AV display adjustment and diagnostics. It records installed versions, effective application/component enabled state, export status, required permission/protection level and this app's permission grant. Package preflight is explicitly distinguished from an actual connection; platform/SELinux restrictions may still reject a bind.

Only the UnitInfo service is bound. `UnitInfoProtocol.getVehicleModel` and `getDestinationCode` issue exactly two read-only `getUnitInformation` calls. The original `IUnitInformationManagerApService$Stub$Proxy.getUnitInformation` assigns transaction `0x21`. Its in/out `SettingData` parcels presence, type, `Parcel.writeValue`, list and integer array; getters send null value/list/array. Reply contains exception header, result status, presence and the returned `SettingData`.

The supplied `VehicleInfoManagerApService$3.onServiceConnected` uses type **4** for destination and casts its value to Integer, then uses type **7** for model and passes `String.valueOf(value)` to `VehicleInfoControl.setModel`. The new client preserves these raw identifiers; it does not translate them into a guessed vehicle year, trim or market. Unsupported or malformed results remain errors/unknown, and one readable identifier can be reported even if the other fails.

The exported JSON also includes Android API/release/model/manufacturer/product/build ID/fingerprint and six manual physical checks. All manual checks begin `NOT_TESTED`. A user can record a pass/failure/not-applicable observation with required notes, timestamp and explicit user-report attribution. Package availability and identity read success never set `independently_verified_hardware` to true. The report is copyable/shareable, and no vendor settings are changed by this screen.

`ValidationTest` covers missing/non-exported/disabled/permission-denied service gates, exact read-only wire requests, package versions, diagnostic signature permission reporting, malformed/partial/rejected identity, timeout and late callbacks, synchronous bind cleanup, cancellation during descriptor lookup, observer reentrancy and manual result attribution. API 28's long version-code accessor is guarded; the rest of the implementation uses APIs available on Android 4.2/API 17.
